## English

**Maintenance continues; no reopening date is set. No production release or admission change was made.** The last successfully checked public stable launcher was 0.2.43. The latest public status request returned HTTP 403, so a fresh status verification is still pending.

Map restoration and separate Private modes are under QA. Five definitions were restored from verified Chinese-original assets: Changban Territory, plus both rulesets for Mycale and Vesuvius. The candidate contains 16 terrains with two rulesets each. Two QA0.2.80 clients verified Vesuvius Territory entry, terrain and minimap, combat, central capture and respawn. Both QA0.2.82 VMs verified separate Private Territory and Private Annihilation entries, their icons and non-overlapping English descriptions. Restored Mycale Annihilation completed with final results, self/public history, lobby return and result delivery for both players. Default/fixed skills, consumables and tree allocations matched for all six deployed units. Further QA found that a map update could silently turn a Territory room into Annihilation. QA0.2.83 preserves the room ruleset, passed 183 Linux and 153 Windows tests, and is installed in both VMs. Live map changes and invitations to a participant with Annihilation selected now retain the server room’s Territory ruleset. Changban Territory also started successfully, with terrain, minimap, the 3500-point target, ordinary-point capture and central capture verified. Changban subsequently completed by base capture, with both results, matching self/public history, six complete loadouts and return to the same room confirmed. The next Mycale Territory round ended immediately with zero duration and insufficient players; its conflicting outcomes were not settled as valid results. After restarting both clients, Mycale Territory completed by base capture; a second round on the same map also completed. Both rounds verified both outcomes, matching self/public histories, six complete loadouts, result delivery and return to the same room. The immediate ending after changing maps remains under investigation, and full map acceptance is incomplete.

QA0.2.84 is installed in both VMs and real game launch and normal exit are verified. Each helper-owned temporary directory was removed after exit while existing files were retained. Recovery after an OS or launcher crash is not accepted yet. Vesuvius Annihilation also completed normally, with both outcomes, matching self/public histories, six complete loadouts and result delivery confirmed. Switching to a new Territory room in the same game processes reproduced an immediate zero-duration, insufficient-player ending; contradictory outcomes were not settled. Both clients’ logs show a brief reconnect notification causing the native game to decide that an alliance has no active human. A fix separating reconnect grace from irreversible departure is under test. Live acceptance of that fix and normal final results for both Vesuvius Territory players remain pending.

Two real QA0.2.73 Private clients completed entry, final results, history storage and result delivery. The owner-first return bug is fixed: a peer returning does not acknowledge your result; your own return delivers it exactly once. QA0.2.76 fixes the unimplemented Private invitation route. Both VMs verified notification, acceptance, room entry and exit, 60-second expiry, and acceptance of a fresh invitation after expiry. Other cases, including invitations during battle, still need acceptance.

All six deployed units recorded default, fixed and selected skills, consumables and tree allocations. Self and public history APIs agreed. Usage statistics exclude old matches without complete snapshots; skill activation counts are not collected. Recorded QA responses render in Japanese, English and Russian, but final Epic sign-in and filtering checks on darask.me remain pending.

QA0.2.74 introduced the restoration to **3500 points and Chinese-original capture settings**, including a base capture amount of 3000 and a 90-second post-capture lock. Capture tables, multipliers and unit capture power were compared with the original. The two-client battle verified the 3500-point HUD, an ordinary point takeover and its 90-second lock. Base capture duration and a timed comparison with the untouched original remain unverified. All weapon/armor stat effects remain disabled; T10-equivalent units and original skill, consumable and tree values are retained.

Further QA reproduced a missing final result on the participant that left around AFK handling; both loadouts and the winning side’s result were stored. The participant’s final result remains unresolved. QA0.2.75 fixes leaving an expired idle Private room, passes 88 related Windows regression tests, and is installed and starts in both VMs. Final live expiry/exit acceptance remains pending.

Full acceptance and production release remain pending: three/four-person parties, disconnect/cancel/reconnect, long sessions, AFK result handling, all unit families, full statistics, update interruption/repair, ban/kick, load and host reboot checks. A persistent reconnect overlay on the main client after battle entry is also under investigation.
